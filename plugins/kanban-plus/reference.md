# The kanban board (Kanban+)

- The board comes with the Kanban+ plugin, enabled by default. With it off there are no kanban tools; say so and point to the plugins screen.
- Cards: `list_kanban_cards`, `get_kanban_card` (the card with its log and comments), `add_kanban_card`, `move_kanban_card`, `take_kanban_card`, `update_kanban_card`, `add_kanban_comment`. Columns in order: `backlog`, `todo`, `doing`, `polish`, `done`; the `move_kanban_card` description gives their labels. A new card goes to `backlog` by default.
- The `id` is like in Jira: the project's prefix and a number (`OS-21`, `TASK-3` for a card of no project); the user refers to tasks by these ids. `project` is a key from `list_projects` or null when the card is not about one project. The project is a field and a filter, not a board.
- A card has a `type` (`task`, `bug`, `story`, `epic`, `chore`), a `priority` (`low`, `normal`, `high`, `urgent`), `labels`, an `estimate` in points and an assignee: `assignee: "user"` when the user took it, `agent` when an agent did.
- Took a task into work: call `take_kanban_card`, and the agent's name appears on the card. The card's log records which tab and session took it; its `sessions` lists the sessions of the tabs that took it. Note what was done, found or decided with `add_kanban_comment`.
- `level` is only on cards of the Claude OS project: `user` for changes in `config/`, `root` for the core (`server`, `web`, `shared`, `e2e`).
- Only the user can delete cards, in the interface.
- Asking: when a session finishes a meaningful piece of work, finds follow-up work, or the user names a task, it may ask the user one short question whether to add or update a card. A card is added only after a yes, never silently; in a work tab adding a card or a board asks the user first.
- Boards: `list_kanban_boards`, `add_kanban_board`, `update_kanban_board`. There are no sprints: every card is on exactly one board (`board` is its id) and in one of its columns. Two boards always exist: `epics` (an epic without a board goes there) and `tasks` (everything else). When the user asks for a board (for a project, a release, a kind of work), add it with a `name`, optionally a `project` (its new cards get that project) and a `goal`, then move cards onto it with `update_kanban_card`. Only the user removes a board, an empty one, in the interface.
- A card is the file `vault/kanban/<id>.md`: the fields in the frontmatter, the description in Markdown below it, the `path` field gives the path. It can be read and edited directly; change the column, the order and the comments with the tools.
