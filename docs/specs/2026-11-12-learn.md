# Learn — spec

Status: implemented · Owner: the user · Date: 2026-11-12

## Intent
The user's own `config/plugins/go-course` is a single course baked into a skill. He wants a plugin that teaches any skill: Claude builds a roadmap, writes each lesson as a clear HTML article, tests him between lessons, works through exercises with him in a Claude tab, and suggests short videos. His Go course becomes one track inside it, imported when he chooses.

## Evidence
- `config/plugins/go-course`: a skill (`SKILL.md`, `program.md` with 12 lessons, `template.html`); progress lives in a `progress.json` in a course folder outside Claude OS. No interface.
- The plugin interface API (`web/src/lib/uiPlugins.tsx`) has file panel parts, slash commands, an overlay and a composer mark: no screen and no burger menu entry.
- `OS_PLUGIN_PERMISSIONS` opens three tab file routes; no plugin can keep its own data. `{pluginData}` (`data/os-plugin-data/<id>`) exists only for `download` dependencies.
- `{pluginDir}` is substituted in MCP configs (`readMcp` in `server/tools/osPluginManifest.ts`), `{pluginData}` is not.
- Sessions cannot edit `data/` (`Edit(<data>/**)` is denied, `server/chat/secrets.ts`); a plugin's MCP server is a separate process and can.
- Documents render HTML in a sandboxed frame without scripts (`prepareDocument`, `DOCUMENT_SANDBOX` in `web/src/lib/documents.ts`).

## Goals
1. A shipped plugin `plugins/learn` ("Learn", with a Russian title in the Russian interface) with a burger menu entry that opens the Learn screen.
2. Tracks with a roadmap of nodes (to do, current, done, skipped), progress, a day streak.
3. A lesson is an HTML article written by Claude, shown sanitized in a frame styled for both themes, with highlighted code.
4. A quiz after the lesson: scored in the browser, every attempt kept; a passed quiz (70% and up) marks the node done.
5. "Practice with Claude" opens a Claude tab in the track's work folder with the lesson and an exercise; Claude grades it and records the grade.
6. Suggested videos per lesson: links Claude proposes, YouTube search links when it cannot check a video.
7. Claude has MCP tools to create a track, read it, write the next lesson, update the roadmap and record a grade, and a skill that says how.
8. Data lives in the plugin's data folder, not in the vault.
9. A course plugin of the user's (such as go-course) is offered for import as a track; nothing is imported by itself.

## Non-goals
- No YouTube API, no fetching of video metadata.
- No editing of the user's go-course plugin.
- No spaced repetition scheduler (the quiz history is kept so one can come later).

## Anti-goals
- A button that does nothing because the plugin's MCP server is missing: generation always goes through a Claude tab, which says what is wrong.
- Scripts from a lesson running in the app.

## Design
Core (the plugin platform, usable by any plugin):
- `ui` contribution `screens: [{ id, title, icon, component }]`: an item in the burger menu (and the command palette) that opens `{ kind: 'plugin', screen: id }`, rendered in the usual sheet inside a `PluginBoundary`. A screen of a plugin that is not (yet) loaded shows a skeleton, then an empty state.
- `host` gains `useApi`, `openChat({ cwd, title, prompt })`, `HtmlFrame({ html, title })` (the documents frame) and `motion` (`Pop`, `Fold`, `Roll`, `useFlip`, `usePresence`).
- Permission `data`: `GET|PUT|DELETE /api/os-plugins/:id/data/<path>` on the plugin's own folder `data/os-plugin-data/<id>`; JSON files only, a folder answers its listing, 5 MB per file, names `[\w.-]`, no dot files. Changes, the plugin's own MCP server's included, invalidate the topic `osPluginData`.
- `{pluginData}` is substituted in `mcp` and `hooks` like `{pluginDir}`.

The plugin, data under `{pluginData}`:
- `tracks/<track>/track.json` (Claude's): title, goal, level, language, work folder, style notes, source, nodes.
- `tracks/<track>/lessons/<node>.json` (Claude's): title, minutes, html, quiz, videos, practice.
- `tracks/<track>/grades.json` (Claude's): practice grades.
- `tracks/<track>/progress.json` (the screen's): read and done marks, quiz attempts, active days.
- MCP server `learn` (stdio, no dependencies): `learn_list_tracks`, `learn_get_track`, `learn_create_track`, `learn_update_roadmap`, `learn_save_lesson`, `learn_record_grade`.
- Skill `learn`: the lesson format (allowed HTML and classes), quiz rules, practice and grading, videos.

Failure paths: the plugin's MCP server is not connected (the Claude tab reports the missing tool); a malformed lesson file (the lesson view shows an error, the rest works); the work folder is missing (the MCP server creates it on track creation; the tab creation error is shown as a toast); the plugin is disabled while its screen is open (empty state).

Touchpoints: `OS_PLUGIN_PERMISSIONS` (described in `root/reference/plugins.md`), `Topic`, `View`, the plugin API in `root/reference/plugins.md` and the `claude-os-plugins` skill.

Rejected: lessons as Claude OS documents (they need a knowledge file per kind and a document tab, and the track would not own them); tools in `rootMcp.ts` (core tools for one plugin); writing files with Claude's Write tool (sessions cannot write `data/`, and nothing would validate them).

## Amendment 2026-11-13: courses are entities inside Learn
The user: a course is not a plugin; it is something Learn holds, which he creates, stores, configures and takes himself.
- A track is the course. The screen creates one by hand (title, goal, level, language, style, roadmap) and edits its settings and roadmap: rename, reorder, add, remove, skip steps; kept steps keep their ids, so lessons and progress stay. Deleting a track was already there.
- A track carries materials: `tracks/<track>/materials/<id>.json` (`title`, `kind` markdown, html or text, `content`), added, viewed, edited and deleted on the screen; MCP `learn_save_material`, `learn_read_material`; `learn_get_track` lists them.
- A lesson's practice can carry an exercise: `files` (relative paths, a stub and its tests) and `check` (the command that checks a solution). The practice tab writes the files into `<workdir>/<node>` unless they are there; MCP `learn_get_lesson` reads a lesson in full.
- The workspace route takes `{ folder }`: a track made on the screen gets `~/learn/<id>`, and a practice tab makes a missing work folder before it opens.
- The learn skill covers what the go-course skill did: next lesson, lesson N, check (run `practice.check`, review, grade), explain, progress.
- The user's go-course plugin was imported into a track (`go-course`, its program as steps, its rules as style, its files as materials) and retired: backed up under `data/backups`, disabled through the plugin API.

## Verification
- `server/tools/osPluginData.test.ts`: the routes need the permission and an enabled plugin, stay inside the folder, write and list JSON; `{pluginData}` reaches the MCP config.
- `server/tools/learnMcp.test.ts`: the MCP server over stdio creates a track, saves a lesson, updates the roadmap, records a grade, keeps materials and exercise files, rejects bad input.
- `e2e/learn.test.ts`: the burger menu opens Learn; a track with a lesson shows the roadmap, the article frame, the quiz that marks the node done, the practice button opening a tab; the import offer for a course plugin, gone once a track names it; a track made and edited by hand; a material added and shown.
- `npm run gate`, `npm run build`, `npm run check:shippable`.

## Claude's calls
- The manifest has no localized name: the plugin row says "Learn", the menu and the screen take their title from the plugin's own strings, Russian in a Russian interface.
- Quiz pass mark 70%; a lesson without a quiz is marked learned by hand.
- The work folder of a track defaults to `~/learn/<track>`.
